# Authoring pages for the documentation site

This directory holds the **canonical sources** of the public documentation site
(ADR 0028; the docs-site mini-PRD). The site under `site/` builds from these files and
from the rest of the repository at build time. Nothing in `site/src/content/` is
committed — it is generated by `npm run sync` in `site/`.

This file is not a page. It is the contract a page follows.

## Where pages live

One file per page, under the namespace it belongs to. The path is the URL:

```
docs/site/index.mdx                       → /
docs/site/start/is-it-for-you.md          → /start/is-it-for-you/
docs/site/operate/recipes/caddy-tailscale.md → /operate/recipes/caddy-tailscale/
```

Namespaces are fixed: `start`, `operate`, `trust`, `skills`, `deliver`, `contribute`,
`reference`, `changelog`. Adding a namespace is a change to the mini-PRD, not to this
directory.

Pages are Markdown. Hub pages (`index.mdx`) may use MDX for Starlight's card components;
nothing else does. Files named `*.intro.md` are prepended to a generated page of the same
name and are not pages themselves. `_data/` holds small YAML files the generators read.

## Frontmatter

```yaml
---
title: Is LQ.AI for you?
description: One sentence that a search result or llms.txt can show.   # required
audience: [operator, evaluator]   # operator | evaluator | author | contributor | partner | agent
status: draft                     # draft | reviewed — rendered as a badge
sources:                          # repo-relative files this page curates or checks its claims against
  - docs/quickstart.md
  - README.md
sidebar:
  order: 2                        # position within the namespace
---
```

`title` and `description` are Starlight's. `audience`, `status` and `sources` are the
site's own. `sources` matters: the page's "checked against" stamp is the newest commit
touching the page **or any of its sources**, so a source that changes makes the stamp move.

## Includes — curation without copies

A page that presents an existing repository file does not copy it. It includes it:

```markdown
<!-- include: docs/quickstart.md -->
<!-- include: docs/INSTALL-MAC.md from="## Install" to="## Troubleshooting" -->
<!-- include: docs/security/threat-model.md shift=1 -->
```

- The path is repository-relative.
- `from` and `to` are exact heading lines in the source; `to` is exclusive.
- The source's H1 is always dropped (the page's `title` replaces it).
- `shift=N` demotes every included heading by N levels.
- Links and images inside the included text are resolved from the source file's own
  location, then rewritten (see below).

A curation page is *an entry sentence, the include(s), onward links*. The entry sentence
says who the page is for and what they will be able to do. A bare include is not a page.

## Links

Write relative Markdown file links, so that GitHub renders them and
`docs/audits/check_doc_links.py` can verify them:

| Target | Write | Becomes |
|---|---|---|
| another site page | `[threat model](../trust/threat-model.md)` | the page's URL |
| a repository file that some page presents | `[quickstart](../../quickstart.md)` | that page's URL |
| any other repository file | `[SECURITY.md](../../../SECURITY.md)` | a GitHub link pinned to the checked commit |
| an image in the repository | `![](../../images/x.png)` | copied into the site |
| a **generated** page | `[changelog](../changelog/index.intro.md)` | that generated page's URL |

A generated page (`/changelog/`, `/skills/catalogue/`, `/skills/coverage/`, the three
`/reference/` tables) has no ordinary Markdown file under `docs/site/`. Link to its
`*.intro.md` companion where it has one — that file exists on disk, so
`docs/audits/check_doc_links.py` can resolve it and GitHub renders it, and the transform
maps it to the generated route. A generated page with no intro file cannot be linked from
a page yet; add the intro file first.

Never write a root-absolute link (`/trust/…`), a hard-coded base (`/lq-ai/…`), or a
`legalquants.github.io` URL. The base path is configuration. A plain repository URL that
happens to contain `github.com/LegalQuants/lq-ai/…` is not a hard-coded base and is fine.

## What the build adds

- The **stamp**: "Checked against `<sha>` · <date>" and the list of sources, in the footer.
- The **status badge** from `status`.
- A **`.md` twin** of every page at the page's URL plus `.md`, and the site-wide
  `/llms.txt` and `/llms-full.txt`.
- **Sidebar** placement from the namespace and `sidebar.order`. A page not reachable from
  the sidebar fails the build (no orphans).

Do not write any of these by hand.

## Tables

A Markdown table renders as one of three shapes, chosen from its shape rather than
written by hand: two columns become a definition list, one-row-per-entity data (most
tables here) becomes a set of records, and a table stays a plain grid only when it is
both short and narrow enough to fit the column. Write the table normally; if the
automatic choice is wrong for one table, override it with a directive comment
immediately above it — `<!-- table: grid -->`, `<!-- table: dl -->`,
`<!-- table: records -->`, or `<!-- table: records key=2 -->` to title the records from
a column other than the first (1-based). The Markdown source is unaffected either way,
so it still reads as a table on GitHub.

## House rules

- Every page ends with a `## Next` section of one to four onward links.
- Every claim about what LQ.AI does traces to a file in `sources`. Where the repository
  does not document something, say so — "not documented as of the checked commit" — rather
  than fill the gap.
- A control whose failure is silent says so and says what the reader can observe instead
  (`:::caution[Silent failure]`).
- Name the professional duty at the point of the decision that engages it
  (`:::note[Professional duty]`), without stating any one jurisdiction's rule as universal.
- License obligations are stated as obligations, with the threshold and the compliant pattern.
- Status words come from `docs/HONEST-STATE.md`: shipped, partial, scaffold, deferred.
- Product name: **LQ.AI**. US spelling, as in the rest of the repository.

The quality rules and the journeys these pages are tested against are in the docs-site
mini-PRD (Annexes A and B).
