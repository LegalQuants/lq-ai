## Recovery preparation

Retain v0.8.0 image digests, deployment configuration and a database backup.
The schema change has a downgrade that restores the old `now()` default; it does
not rewrite timestamps already recorded under 0069. Reverting application code
does not undo those rows. Rehearse any full database restore only on disposable
data, and plan for writes made after the backup.

For a hand-run stack, a fallback must repin **all four images** to verified v0.8.0
digests and recreate the API/workers consistently. It restores the #668 bug and
the old timeout. For the desktop, the v0.9.0 launcher reasserts its baked image tag
on launch; merely editing its generated `.env` is not a durable rollback. Use the
previous verified launcher with a compatible snapshot and verify the effective
pin before starting. Never reuse a released tag for different source or delete
volumes as a recovery step.
