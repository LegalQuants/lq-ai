# v0.9.1 — matter sharing, admin account controls and tabular provenance

This is a **patch release**. Nothing in it requires an operator to touch a working install, which is
what makes it a patch under ADR 0025 (decision 3, as amended on 2026-10-12). Migrations 0070 to 0079
apply at startup, every new environment variable is optional and its default keeps current
behavior, and the pgvector extension update that accompanies the new database image is optional.
Read *Behavior changes* for what users will notice without anyone configuring anything.

The 57 commits since v0.9.0 bring matter sharing with ethical screens, admin account creation and
password reset, admin distribution of community skills, real citation provenance and cost records
for tabular review, a fail-closed check on quotations attributed to fetched authorities, and an
experimental **New harness** model that is off by default. The gateway gains Bedrock protocol
support and moves its MCP client past two upstream advisories.

---

## Before upgrading

- **Keep a database backup, the previous image digests and your gateway configuration.** Apply or
  roll back `api`, `arq-worker` and `ingest-worker` together. The api applies migrations 0070 to
  0079 when it starts; do not run host-side Alembic against a live stack.
- **Rolling back to v0.9.0 may need the backup.** Migrations 0074 to 0077 refuse to downgrade while
  the run data they added is retained, and 0078 refuses until queued object erasure has drained. Once
  runs or matter sharing have been used, returning to v0.9.0 means restoring the pre-upgrade
  database with the previous images. Downgrading 0079 drops the minted tabular citations.
- **Hand-run release stacks:** take the new `docker-compose.release.yml` with the images and set
  `LQ_AI_IMAGE_TAG=v0.9.1`. The new file carries the storage pins below and forwards the new
  optional settings. The desktop launcher does this for you.
- **Storage images.** Both Compose recipes move to pgvector 0.8.7 on PostgreSQL 16.15 and RustFS
  1.0.3, and Helm's RustFS pin follows. RustFS now mounts its volume with `nocopy`, so a fresh
  install passes the existing init gate; existing volume contents are untouched. The pgvector
  `ALTER EXTENSION vector UPDATE` step in the
  [storage image runbook](../runbooks/storage-image-updates.md) is optional for 0.8.7: its script
  only changes catalog comments, and the fixed library loads when Postgres restarts. *(#755, #731)*
- **Access tokens issued before the upgrade stop verifying**, because tokens now carry a credential
  version (#715). The web client and the Word add-in renew them through their refresh sessions,
  so signed-in users stay signed in. A script that holds only an access token signs in again.
- **A `type: bedrock` gateway entry without `bedrock_protocol` is still skipped at startup**, as it
  was in v0.9.0. Use the new entry shape in `gateway.yaml.example` only if you want Bedrock. *(#744)*

An installation on v0.9.0 needs nothing else. Earlier installations must also follow the
[v0.9.0](v0.9.0.md) and [v0.8.0](v0.8.0.md) notes and the
[MinIO-to-RustFS runbook](../runbooks/minio-to-rustfs.md). Preserve deployment volumes.

## Behavior changes

None of these needs configuration. Each is something a user may notice after the upgrade.

- **An unsupported quotation attributed to a fetched authority now fails.** Quotes are bound to the
  authority they cite before verification, and one the authority does not support is stored as a
  FAIL row, so the citation ledger and the fiduciary gate flag it. Unattributed quotes and
  authorities not fetched that turn are handled as before; a body that fails to load fails
  closed. *(#405)*
- **A tabular cell whose value cannot be found in its source shows no citation**, in the results
  view and in CSV/XLSX exports, rather than a display-only link to the chunk. Cells whose value is
  found carry offset-bearing provenance, and source highlighting in the citation dialog is
  repaired. Executions saved before this release keep their existing citation IDs. *(#420)*
- **Tabular results record the routed tier and the reported cost of each cell**, including failed
  extractions, and distinguish unknown from partial costs. Ensemble verification stops granting
  passes when reported spend plus reserved estimates would exceed the confirmed estimate;
  extraction continues and the results show the halt reason and skipped cell count. Final charges
  can still exceed the estimate. *(#421, #423)*
- **Autonomous analysis falls back to the `smart` alias** when neither the trigger nor the skill or
  playbook names a model. The previous fallback, `claude-opus-4-7`, was not a routable name
  (#681). `LQ_AI_AUTONOMOUS_DEFAULT_MODEL` overrides it. *(#717)*
- **Skill reference files are readable on demand again** in chat and background runs, up to 64 KiB
  per read with the file size and continuation reported. `LQ_AI_SKILL_REFERENCE_READ_ENABLED=false`
  turns this off. *(#658)*
- **Playbook retrieval matches any of a position's keywords** again, not only passages containing
  all of them. *(#720)*
- **The composer warns when an attached file was still processing at send time**, without claiming
  its content reached the model. *(#689)*
- **Viewers and auditors can no longer start, approve or reject an orchestration run.** A v0.8.0
  demonstration run still in flight at the upgrade stops at its next admission. *(#599)*
- **The web interface uses the approved LQ.AI design primitives** (ADR 0043) and their semantic
  tones. LQ.AI remains light-theme only. *(#282, #405)*

## New capabilities

- **Matter sharing with ethical screens.** A matter's leads, starting with its owner, can add
  members, screen people out and set a share scope; `org` scope gives every unscreened user read
  access. Existing matters stay personal, with their owner recorded as lead. Administrators and
  auditors get no automatic access to matter content: an unscreened administrator can manage
  access policy and recover ownership without joining a matter, and each change is audited with
  its reason. Erasure protects retained sources, and object deletion runs through a durable
  queue. (ADR 0042) *(#719)*
- **Admin account controls.** Administrators can create accounts and reset passwords from the
  existing role management card. A password change invalidates that user's access and MFA tokens
  and revokes their refresh sessions at once. Temporary passwords are returned with
  `Cache-Control: no-store` and cleared when dismissed. *(#715)*
- **Admin distribution of community skills.** Administrators can review and install community
  skills for their teams, with the source, exact content hashes and distribution recorded as
  write-once provenance. Plugin and source management remain deferred (DE-404). (ADR 0041) *(#710)*
- **Tabular redline reports and summary memos.** Selected columns can be drafted into a redline
  per row or a summary of a column, with immutable instruction provenance. Outputs are owner-scoped
  and kept after their source documents are deleted. Routing restrictions and operator
  anonymization apply. (ADR 0040) *(#418)*
- **Matter context proposals in the Matter workspace.** Pending context proposals appear on the
  Matter page, and Matter context changes only after confirmed opt-in and explicit acceptance.
  *(#412)*
- **A notification bell for autonomous users.** It appears only after the server confirms the
  signed-in user's autonomous opt-in, with an unread count, the ten newest unread items and
  read actions. *(#413)*
- **New harness (experimental, off by default).** An entry in the chat's model picker that either
  answers directly or proposes a plan of one to four tasks for the owner to approve. Sub-agents
  then work each task with the tools the plan grants, and the answer's quotations are checked
  against the files they name. It runs only when `LQ_AI_NEW_HARNESS_ENABLED=true` and a direct
  gateway provider and model with explicit rates are set; see
  [the UAT runbook](../runbooks/adr38-runs-in-chat-uat.md) for sizing. (ADR 0038) *(#599)*
- **Bedrock in the gateway.** Claude Messages, Chat Completions and stateless Responses through
  Bedrock's compatible APIs, authenticated with `AWS_BEARER_TOKEN_BEDROCK`. Streams that are
  malformed, failed or truncated are rejected. *(#744)*
- **An operator ceiling on tool egress.** `LQ_AI_TOOL_MAX_EGRESS_TIER` (1 to 5, unset by default)
  caps governed chat and autonomous tool egress. The lowest of it, the matter's own ceiling and
  the execution scope's ceiling applies, and each tool call records which one bound it. Recreate
  `api` and `arq-worker` after changing it. *(#637)*
- **Smaller gateway and observability options.** Chat requests accept an optional reasoning
  effort, and the arq worker's spans carry `LQ_AI_ARQ_WORKER_OTEL_SERVICE_NAME` so one trace spans
  the request, worker, gateway and provider. *(#599)*

## Security

- **The gateway's MCP client moves to `mcp` 1.30.** 1.28.1 followed an MCP server's cross-origin
  redirects (GHSA-5h93-6whr-6q8j), which could send a tool call's body to a host the operator never
  allowlisted, and fetched server-chosen `$ref` URLs when validating tool output
  (GHSA-rwrf-2pqf-9j8j). A new integration test proves nothing reaches a redirect's second
  origin. *(#736)*
- **Five authorization findings across inference and document workflows are closed** as part of
  matter sharing. *(#719)*
- **Password changes take effect immediately** across access tokens, MFA tokens and refresh
  sessions. *(#715)*
- **Autonomous retrieval records one ownership-denied audit outcome per refusal**, without
  duplicating the generic error audit. *(#684)*
- **Citation cost calibration runs in a savepoint**, so an optional calibration SQL error no
  longer aborts the caller's transaction and its citation, ledger, gate and audit rows. *(#752)*

## Honest scope

- **Bedrock has not been verified against a real AWS account.** That check is tracked in #745.
  Choose an entitled model or profile for your region; see
  [Bedrock verification](../bedrock-verification.md).
- **New harness is experimental.** Pseudonymization follows the gateway's `anonymization` setting
  for the tier the run's route resolves to, and covers runs only; ordinary chat is not covered
  (DE-269). Not yet built: the access module (ADR 0038 D8), pseudonymization by source and
  destination (DE-409), sources and connectors in runs (DE-411) and runs on a hosted provider.
- **The notification bell's acceptance checks are still open** (DE-324): stale and failed
  preference loads, session changes, keyboard and focus, and phone and desktop layouts.
- **Matter sharing cannot revoke what has already left.** Issued storage URLs and downloaded
  copies stay valid. Shared attachments and running autonomous sessions must be reconciled before
  an ownership transfer, and infrastructure operators remain outside API-layer isolation.
- **Accessibility coverage is partial.** The per-PR checks cover seven route states; broader
  coverage and the manual audit remain open (DE-232, #386). LQ.AI supports light theme only.
- **Gateway file secrets (#601) are not in this release.**
