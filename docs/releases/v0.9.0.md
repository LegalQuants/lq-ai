# v0.9.0 — emergency release for required skill inputs in web chat

> **Draft — do not publish yet.** Prepared on 2026-10-08 for the emergency release
> prompted by [#668](https://github.com/LegalQuants/lq-ai/issues/668).
> [Fix #669](https://github.com/LegalQuants/lq-ai/pull/669) is still open at preparation
> time. The behavior described below depends on that fix merging. Follow the
> [release-readiness checklist](v0.9.0-readiness.md) before tagging or publishing.

This release restores the required-input form when a skill is attached in web chat.
Since v0.8.0, the gateway enforces required inputs, but the web client's YAML parser
did not recognize the nested frontmatter used by built-in skills. Attaching NDA
Review therefore showed no form and sending failed with `skill_input_missing`.
Eleven built-in skills declare inputs in the affected shape; NDA Review was the
reported reproduction.

This is a **minor release under [ADR 0025](../adr/0025-release-versioning-and-pipeline-ordering.md)**.
It includes the fixes already on main since v0.8.0, including #664's change to timeout
defaults. The emergency trigger does not make that accumulated range a patch.

## Read before upgrading

- **The API-to-gateway timeout rises from 60 to 900 seconds.** Read, write and pool
  timeouts use `LQ_AI_GATEWAY_TIMEOUT_SECONDS`; connection establishment is capped at
  `min(value, 10 seconds)`. The setting must be positive and finite. Streaming uses
  the same budget; health and configuration probes retain short overrides. Review
  proxy/client budgets and workload expectations before upgrading. Keep the API
  budget above every gateway adapter's `timeout_s` (600 seconds by default), so the
  gateway can report its failure first. This bounds HTTP inactivity, not total
  request duration. For hand-run deployments, set the value in `.env` if needed and
  recreate `api`, `arq-worker` and `ingest-worker` together. A 60-second override
  reproduces the old API budget but can still cut off a slower adapter.
  ([#664](https://github.com/LegalQuants/lq-ai/pull/664))
- **A declared compatible-provider key must resolve.** An `openai_compatible`
  provider with an unset or empty declared key now gets no adapter and is skipped
  during model discovery. For an authenticated provider, supply its declared key.
  For an intentionally keyless local server, remove the key source or set
  `api_key_env: ''`, as the vLLM example does. Restart the gateway after changing
  its configuration. This checks key presence, not validity.
  ([#660](https://github.com/LegalQuants/lq-ai/pull/660))
- **Application migration 0069 changes future audit timestamps.** The Alembic head
  advances from `0068` to `0069`. Startup applies the change to the `audit_log.timestamp`
  default, from transaction-start `now()` to insertion-time `clock_timestamp()`.
  Existing rows retain their timestamps. Wall-clock time does not guarantee event
  order. Preserve a database backup before upgrading and recreate the API and both
  workers together; do not run host-side Alembic against a live stack.
  ([#651](https://github.com/LegalQuants/lq-ai/pull/651))

An installation already on v0.8.0 needs no new object-store migration for this
release. An installation upgrading from v0.7.x or earlier must also follow the
[v0.8.0 migration notes](v0.8.0.md) and the
[MinIO-to-RustFS runbook](../runbooks/minio-to-rustfs.md). Do not remove deployment
volumes to upgrade.

## Required skill inputs in web chat

With #669 included, attaching a skill loads its input schema from
`GET /api/v1/skills/{name}/inputs`, using the backend's user > team > built-in
resolution. Required inputs appear immediately; optional inputs are behind
“More options”. The client-side YAML input parser is removed.

A required `document` input can use pasted text or attached files that have
finished ingestion. The form binds their names; document text continues to travel
through the existing `file_ids` path. Files still processing do not count. Send is
held until schemas load and required inputs are supplied. A schema-load error
offers Retry. Multiple attached skills have separate fields.

This corrects the statement in the v0.8.0 notes that “the web composer already
supplies them”: it did not supply required inputs for built-in skills.
([#669](https://github.com/LegalQuants/lq-ai/pull/669),
[#668](https://github.com/LegalQuants/lq-ai/issues/668))

## Other fixes and maintenance since v0.8.0

- Ollama tool calls now survive ordinary and streaming response translation,
  tool arguments are converted to the provider's shape, and tool-only output
  counts as usable output.
  ([#649](https://github.com/LegalQuants/lq-ai/pull/649))
- Gateway `${VAR:-default}` expansion now applies the default when a variable is
  empty as well as unset.
  ([#650](https://github.com/LegalQuants/lq-ai/pull/650))
- MCP session errors expose a bounded description of their causes and preserve
  upstream HTTP status, excluding response bodies and full request URLs.
  ([#659](https://github.com/LegalQuants/lq-ai/pull/659))
- File endpoints return `ingestion_error` when ingestion failed, making the failure
  reason available to clients.
  ([#655](https://github.com/LegalQuants/lq-ai/pull/655))
- Failed autonomous analysis dispatches receive an error audit row; failures in
  postprocessing are distinguished from dispatch failures.
  ([#656](https://github.com/LegalQuants/lq-ai/pull/656))
- OCR citation normalization converges before matching, making chained character
  substitutions idempotent.
  ([#652](https://github.com/LegalQuants/lq-ai/pull/652))
- Property-based regression checks and a pinned synthetic PII leakage corpus add
  test coverage; API tests are type-checked in CI.
  ([#435](https://github.com/LegalQuants/lq-ai/pull/435),
  [#439](https://github.com/LegalQuants/lq-ai/pull/439),
  [#440](https://github.com/LegalQuants/lq-ai/pull/440))
- Nightly Cypress uses the browser-reachable API address, and the contribution
  coverage map documents ownership and routing.
  ([#630](https://github.com/LegalQuants/lq-ai/pull/630),
  [#666](https://github.com/LegalQuants/lq-ai/pull/666))

All four images (`api`, `gateway`, `web`, `proxy`) are rebuilt as `v0.9.0`. The
substantive runtime changes are in API, gateway and web; the proxy has no source
change in the inspected range. `desktop-v0.9.0` follows image verification and pins
the launcher to `v0.9.0`; its version bump delivers that image set.

## Known limits

The input-form fix covers skills attached through the composer. Sticky skills
after reopening a chat still lose their inputs (DE-398), and a send-time slash
fallback that attaches a skill server-side still supplies no inputs (DE-399).
Use a fresh chat and attach the skill through the picker to use its form. The
Enhance Prompt review screen, per-input file selection and legacy flat input
lists remain outside this fix (DE-010).

#669 reports successful unit/type/build checks and one completed pasted-text NDA
review on an earlier dev build against v0.8.0. Attached-file turns were accepted
but timed out; the final production image and the combined #669 + #664 path still
need the release rehearsal. These are preparation-time limits, not release
verification results. Record fresh evidence in the readiness checklist.
