## Breaking changes

- **The API-to-gateway inactivity budget rises from 60 to 900 seconds.**
  Read, write and pool timeouts use `LQ_AI_GATEWAY_TIMEOUT_SECONDS`; connection
  establishment is capped at `min(value, 10 seconds)`. Streaming uses the same
  budget; short health/configuration probes retain their overrides.
  ([#664](https://github.com/LegalQuants/lq-ai/pull/664)) — @houfu and @sergiomaldo.
  **What you need to do:** Review proxy/client budgets and workload expectations.
  The setting must be positive and finite, and should exceed every gateway
  adapter's `timeout_s` (600 seconds by default) so the gateway reports failures
  first. For hand-run deployments, set the value in `.env` when needed and recreate
  `api`, `arq-worker` and `ingest-worker` together. This bounds HTTP inactivity,
  not the request's total duration.
  **Undo:** The review records an irreversible configuration-contract class.
  Setting the value to 60 restores the old API inactivity budget, while retaining
  the new connection cap; restoring the exact previous transport behavior requires
  the previous deployment/source. A short API budget can again interrupt slower
  adapter calls. See the coordinated rollback notes in the readiness checklist.
- **A declared compatible-provider key must resolve before the provider is used.**
  An `openai_compatible` provider naming an unavailable key gets no adapter and is
  skipped during discovery. This entry is included because an intentionally
  keyless server with an unset declared key source behaved differently before,
  even though the PR is labelled `bug` rather than `breaking-change`.
  ([#660](https://github.com/LegalQuants/lq-ai/pull/660)) — @houfu.
  **What you need to do:** Supply the declared key for an authenticated provider.
  For an intentionally keyless local server, remove the key source or set
  `api_key_env: ''`, as the vLLM example does. Restart the gateway after editing
  configuration. Presence is checked; validity is not.
  **Undo:** The review records an irreversible provider-contract class. Correcting
  an intentionally keyless entry restores that server's availability; returning
  to the old declared-but-unavailable-key behavior requires reverting the provider
  change or the deployment. Retain configuration and image digests for rollback.

## Known limits and verification

The form covers skills attached through the composer. Kept-on skills after
reopening a chat still lose their inputs (DE-402); the send-time slash fallback
still supplies no inputs (DE-403). Use a fresh chat and the picker to reach the
form. The Enhance Prompt review screen, per-input file selection and legacy flat
input lists remain outside this fix (DE-010).

The v0.8.0 statement that the web composer already supplied built-in required
inputs was inaccurate; the accompanying correction points to #668 and this fix.
#669 reports completed pasted-text NDA reviews on both the earlier and final dev
builds against v0.8.0, plus a final-build schema-failure/send-hold/Retry exercise.
Attached-file turns in those earlier dev-build checks were accepted but timed out.
The subsequent combined #669 + #664 local arm64 production rehearsal completed
the pasted-input answer; the maintainer confirmed completed attached-document
answers, ordinary chat, separate skill fields, and schema-failure Send blocking
with Retry recovery. The agent verified pending-file Send blocking and ready-file
binding. A separate v0.8.0 upgrade preserved chats, ready files and downloaded
bytes, reached migration 0069, and completed NDA Review through the upgraded API
using the retained file. That saved answer rendered in the browser. These
candidate results are recorded in the readiness checklist and do not replace
published-image or signed-desktop checks.
Its [four final-head CI checks](https://github.com/LegalQuants/lq-ai/actions/runs/37708031627)
passed; that is separate from those production-image gates.

The desktop light-theme composer passed at 1280 × 900. At 390 × 844, side panes
obscured the composer and required inputs shrank to 18px wide. This phone-width
failure remains unresolved; it has not been classified as a new regression.
