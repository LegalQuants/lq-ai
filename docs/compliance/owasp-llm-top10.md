## Scope and limits

This is a **self-assessment by the project**, not an audit, an attestation, or a certification. It maps each 2025-edition risk to LQ.AI's architecture: what the codebase enforces structurally, what the operator configures, what risk remains, and what the operator must own. Every structural claim cites a repository file and inclusive line range so a reviewer can verify it in source rather than take the claim on faith. Where a control does not exist, the row says so explicitly (`no evidence yet`) instead of gesturing at alignment — the project's conservative-posture rule ([CLAUDE.md](../../CLAUDE.md), [`docs/HONEST-STATE.md`](../HONEST-STATE.md)) applies to this document as much as to any release note.

Certifications attach to the operating organization, not to software. LQ.AI is software the operator deploys and runs; this mapping is the project's contribution to the operator's own AI-security review, not a substitute for it.

## How to read this document

Each risk section has five fields:

1. **Threat as it applies to LQ.AI** — self-authored description against the trust boundaries in [`docs/security/threat-model.md`](../security/threat-model.md).
2. **Structural controls (in code)** — present in the reviewed source snapshot; each claim cites a file and inclusive line range, with configuration and failure limits called out separately.
3. **Operator-configured controls** — defaults and knobs the operator tunes; the control exists only if the operator turns it on or sets it correctly.
4. **Residual risk** — what is not mitigated today, with the deferred-enhancement (DE-XXX) reference where one exists.
5. **Operator responsibility** — what the operator must do to close or accept the residual risk.

Evidence links pin source files to the reviewed commit. Each structural bullet also carries a machine-readable `code-cite` comment (`path:start-end`). Run `python scripts/check-compliance-citations.py` to check that the files, inclusive ranges and local document links exist in the candidate checkout; CI runs the same checker and its regression tests. This checks evidence locations, **not the truth of a claim**, release artifacts or mitigation effectiveness. Source changes require renewed substantive review even when ranges still exist.

Ownership vocabulary used throughout (per the project's compliance-pack taxonomy): **structural-in-code**, **operator-configured**, **shared**, **residual**, **out-of-scope**.

A load-bearing scope fact used in several rows: **LQ.AI trains and fine-tunes no models.** The repository contains no training pipeline, no fine-tuning jobs, and no model weights; all inference is bring-your-own-keys against operator-chosen providers (or operator-hosted Ollama at Tier 1), routed through the Inference Gateway — the component holding provider keys and brokering inference/tool-provider egress ([`gateway/`](../../gateway/), [PRD §4](../PRD.md#4-the-lq-ai-inference-gateway)). Training-time risks therefore reduce to the operator's provider and model choice, governed by the Inference Tier model.

## LLM01:2025 — Prompt Injection

**Threat as it applies to LQ.AI.** LQ.AI's daily input is adversarial by profession: counterparty contracts, opposing filings, and third-party documents are ingested into knowledge bases, attached to chats, and run through skills. Any of these — plus external tool results (case-law text, MCP connector output) — can carry embedded instructions attempting to steer the analysis, exfiltrate chat context, or trigger tool calls. This is the risk PRD Appendix E names as "the genuinely-hard problem"; the project explicitly does not claim immunity.

**Structural controls (in code).**

- Skill prompt assembly uses bounded regex `{{var}}` substitution — no template engine, no expression evaluation ([ADR 0007](../adr/0007-skill-prompt-assembly.md); `gateway/app/skills/assembler.py`). Evidence: [assembler.py:84–86](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/skills/assembler.py#L84-L86) <!-- code-cite: gateway/app/skills/assembler.py:84-86 -->; [assembler.py:182–233](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/skills/assembler.py#L182-L233) <!-- code-cite: gateway/app/skills/assembler.py:182-233 -->.
- **Structural hardening, not isolation.** Unconsumed caller-supplied skill inputs are rendered as a single-line **JSON envelope** under an untrusted-content policy line, so a newline, fence or heading inside a value cannot open a new section; placeholder-consumed inputs stay in the skill text with any input-created assembler heading **marker-escaped** (backslash-escaped) so it cannot forge a boundary (`gateway/app/skills/assembler.py`; [ADR 0007, amendment of 2026-09-02](../adr/0007-skill-prompt-assembly.md)). This preserves the structure of the prompt. It does **not** lower the authority of those bytes: skill inputs, retrieved knowledge-base chunks and attached documents are still placed in the *system* message, the model's instruction channel. Evidence: [assembler.py:124–179](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/skills/assembler.py#L124-L179) <!-- code-cite: gateway/app/skills/assembler.py:124-179 -->; [assembler.py:219–233](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/skills/assembler.py#L219-L233) <!-- code-cite: gateway/app/skills/assembler.py:219-233 -->; [chats.py:1501–1605](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/api/chats.py#L1501-L1605) <!-- code-cite: api/app/api/chats.py:1501-1605 -->.
- Chat tool results are a different path and are already separated: each result (or refusal) is fed back to the model as a `role="tool"` message, not merged into the system prompt (`api/app/chat/tool_loop.py`). Evidence: [tool_loop.py:146–171](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/chat/tool_loop.py#L146-L171) <!-- code-cite: api/app/chat/tool_loop.py:146-171 -->.
- Built-in skills are open-source work product (`skills/*/SKILL.md`, e.g. `skills/nda-review/SKILL.md`), so a reviewer can inspect their instructions before use. This does not imply that operator-authored skills or all session context are public. Evidence: [SKILL.md:1–60](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/skills/nda-review/SKILL.md#L1-L60) <!-- code-cite: skills/nda-review/SKILL.md:1-60 -->.
- An injection that escalates to *action* hits the governed tool chokepoints: chat tool calls pass through `governed_tool_invocation` (`api/app/tools/governance.py`) and tools marked destructive or requiring confirmation pause for explicit in-chat human approval before execution (`api/app/chat/tool_loop.py`; `web/src/lib/lq-ai/components/ToolGatePrompt.svelte`). Autonomous work passes through the single `guarded_tool_call` chokepoint under the R5/R6/R4 brakes (`api/app/autonomous/guard.py`). Evidence: [tool_loop.py:867–905](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/chat/tool_loop.py#L867-L905) <!-- code-cite: api/app/chat/tool_loop.py:867-905 -->; [governance.py:219–281](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/tools/governance.py#L219-L281) <!-- code-cite: api/app/tools/governance.py:219-281 -->; [guard.py:253–416](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/autonomous/guard.py#L253-L416) <!-- code-cite: api/app/autonomous/guard.py:253-416 -->.
- An injection that fabricates authority is bounded by the Citation Engine: recorded candidates rejected by every routed verification stage remain unverified (`api/app/citation/verification.py`), and recorded FAIL assertions flag the fiduciary gate (`api/app/citation/gate.py`). Semantic-judge support is distinct from character verification. Evidence: [verification.py:553–586](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/citation/verification.py#L553-L586) <!-- code-cite: api/app/citation/verification.py:553-586 -->; [gate.py:25–98](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/citation/gate.py#L25-L98) <!-- code-cite: api/app/citation/gate.py:25-98 -->.
- An injection that smuggles an exfiltration URL into a tool call is bounded by the SSRF-guarded egress allowlist — HTTPS-only, per-provider host allowlist, public-IP resolution check (`gateway/app/providers/tool/egress.py`). Evidence: [egress.py:37–57](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/providers/tool/egress.py#L37-L57) <!-- code-cite: gateway/app/providers/tool/egress.py:37-57 -->.

**Operator-configured controls.** Tier policy (`allowed_tiers_global`, per-skill `minimum_inference_tier`; `gateway.yaml.example`, `gateway/app/tier_floor.py`) bounds which providers see sensitive context. Tool providers and MCP connectors are off by default and admin-enabled (`gateway.yaml.example` `tool_providers`; `api/app/api/admin_mcp.py`). The autonomous layer is per-user opt-in, off by default (`User.autonomous_enabled`).

**Residual risk.** **Untrusted-content isolation remains deferred** ([DE-388](../PRD.md#9-deferred-enhancements-and-identified-future-work), needs an ADR): until skill inputs, retrieved chunks and attached documents move out of the system message, the envelope and marker escaping above are integrity measures, not a trust boundary, and an instruction inside a counterparty document reaches the model with system-message authority. There is also **no injection-pattern detection shipped**: the prompt-injection pattern library is deferred ([DE-110](../PRD.md#9-deferred-enhancements-and-identified-future-work)) and no detection rates are measured ([DE-239](../PRD.md#9-deferred-enhancements-and-identified-future-work)) — `no evidence yet` on both. A sophisticated injection can still shape prose output that carries no citations and triggers no tool call; the verification layers do not catch that class.

**Operator responsibility.** Human-in-the-loop review of all work product (the profession's existing duty) is the operating mitigation for the residual class. Treat every counterparty document as untrusted input; keep the tool-confirmation gate on; vet MCP connectors before registering them.

## LLM02:2025 — Sensitive Information Disclosure

**Threat as it applies to LQ.AI.** The system processes the most disclosure-sensitive content a company holds: privileged communications, client-confidential contracts, matter files. Disclosure paths are: content leaving to an inference provider, secrets or content landing in logs and audit rows, cross-tenant reads inside the deployment, and provider-side retention.

**Structural controls (in code).**

- The gateway brokers inference and external-tool provider traffic; the backend uses `GatewayClient` for that boundary (`api/app/clients/gateway.py`). This is a provider-egress boundary, not a claim that the backend never contacts deployment services such as object storage. Provider-key resolution stays in the gateway (`gateway/app/secrets.py`). Evidence: [gateway.py:137–169](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/clients/gateway.py#L137-L169) <!-- code-cite: api/app/clients/gateway.py:137-169 -->; [secrets.py:151–189](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/secrets.py#L151-L189) <!-- code-cite: gateway/app/secrets.py:151-189 -->.
- The Anonymization Layer is shipped and wired on the request path: pseudonymization before provider dispatch, streaming-aware rehydration on response (`gateway/app/anonymization/middleware.py`, wired in `gateway/app/api/inference.py`; recognizers in `gateway/app/anonymization/engine.py`). The pseudonym mapping is per-request, in-memory only — never persisted, never logged. Evidence: [middleware.py:62–163](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/anonymization/middleware.py#L62-L163) <!-- code-cite: gateway/app/anonymization/middleware.py:62-163 -->; [mapper.py:35–79](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/anonymization/mapper.py#L35-L79) <!-- code-cite: gateway/app/anonymization/mapper.py:35-79 -->; [inference.py:683–697](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/api/inference.py#L683-L697) <!-- code-cite: gateway/app/api/inference.py:683-697 -->; [inference.py:1227–1235](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/api/inference.py#L1227-L1235) <!-- code-cite: gateway/app/api/inference.py:1227-1235 -->.
- Secrets at rest: the gateway supports Fernet-encrypted provider API keys under an operator master key (`gateway/app/secrets.py`; [`docs/security/encrypted-keys.md`](../security/encrypted-keys.md)); plaintext environment-key configuration also exists and must be protected by the operator. Per-user MCP OAuth tokens use Fernet (`api/app/security/encryption.py`). Evidence: [secrets.py:72–87](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/secrets.py#L72-L87) <!-- code-cite: gateway/app/secrets.py:72-87 -->; [secrets.py:151–189](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/secrets.py#L151-L189) <!-- code-cite: gateway/app/secrets.py:151-189 -->; [encryption.py:167–214](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/security/encryption.py#L167-L214) <!-- code-cite: api/app/security/encryption.py:167-214 -->.
- Tool-governance rows store an argument digest rather than raw tool arguments (`api/app/models/tool_call_log.py`); routing rows store provider/model/tier, token counts and cost estimates (`gateway/app/routing_log.py`). The Citation Ledger is a referencing index without source payloads (`api/app/models/citation_ledger_entry.py`). This is not a blanket guarantee about every audit field: general audit details and privilege metadata can include operator-authored names (`api/app/audit.py`). Evidence: [tool_call_log.py:29–94](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/models/tool_call_log.py#L29-L94) <!-- code-cite: api/app/models/tool_call_log.py:29-94 -->; [routing_log.py:55–88](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/routing_log.py#L55-L88) <!-- code-cite: gateway/app/routing_log.py:55-88 -->; [citation_ledger_entry.py:25–102](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/models/citation_ledger_entry.py#L25-L102) <!-- code-cite: api/app/models/citation_ledger_entry.py:25-102 -->; [audit.py:82–110](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/audit.py#L82-L110) <!-- code-cite: api/app/audit.py:82-110 -->.
- Tenancy: file and knowledge-base API entrypoints enforce owner scope before returning content (`api/app/api/files.py`, `api/app/api/knowledge_bases.py`). Internal helpers rely on callers to establish authorized resource IDs; this does not assert that every internal SQL query repeats an owner predicate. Evidence: [files.py:507–537](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/api/files.py#L507-L537) <!-- code-cite: api/app/api/files.py:507-537 -->; [knowledge_bases.py:95–166](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/api/knowledge_bases.py#L95-L166) <!-- code-cite: api/app/api/knowledge_bases.py:95-166 -->.

**Operator-configured controls.** Anonymization ships **disabled by default** (`anonymization.enabled: false` in `gateway.yaml.example`) — enabling it, choosing `apply_at_tiers`, and selecting entity types are operator decisions. Tier policy determines which provider terms (ZDR, no-training) govern outbound content; Tier 1 routes inference to local Ollama; separately enabled external tools have their own egress policy. Anonymization also skips privileged requests, request opt-outs and tool-role messages, as well as marked retrieval context (`gateway/app/anonymization/middleware.py`).

**Residual risk.** Recognizer recall/precision on representative legal-document corpora remains **empirically unmeasured** ([DE-282](../PRD.md#9-deferred-enhancements-and-identified-future-work)). A [published synthetic leakage baseline](../quality/pii-leakage-rates.md) measured 10/10 organization names surviving the engine under the recorded configuration ([DE-397](../PRD.md#de-397--anonymization-layer-never-pseudonymizes-organization-entities-presidio-default-suppression)); it also records misses or partial leaks in other classes. These are engine-level synthetic results, not end-to-end provider-payload leakage rates or a legal-corpus benchmark. A recognizer miss can disclose unredacted content to the provider. Source-document pseudonymization (DE-269) and per-request salting (DE-274) are open. By design, retrieval context is sent to the provider intact (anonymization retrieval-context skip) so citation grounding works — the operator's tier choice is the control for that content. A provider that has already received content is outside the trust envelope (threat model, out-of-scope threats).

**Operator responsibility.** Turn anonymization on where required and read [`docs/security/anonymization.md`](../security/anonymization.md) §"What's validated vs what's unvalidated" before relying on it; route privileged matters at Tier 1 or under enterprise ZDR terms; encrypt backups; manage TLS and key custody.

**Threat as it applies to LQ.AI.** Four supply chains converge: Python/JS dependencies (including the forked OpenWebUI frontend), the models themselves, community-contributed skills, and external tool providers (MCP connectors, research sources).

**Operator-configured controls.** Which providers, models, connectors, and community skills are enabled is entirely operator-chosen; nothing external is on by default.

**Residual risk.** Release signing, SPDX SBOM attestations and build-provenance workflows have landed. Releases through **v0.7.1** use the calling release workflow for provenance (Build Level 2); the isolated reusable builder supports **Build Level 3 for subsequent releases**, per [`docs/security/releases/README.md`](../security/releases/README.md). Model weights and provider-side model supply chains are out-of-scope for the project and in-scope for the operator's provider due diligence. The OpenWebUI fork carries inherited upstream code (HONEST-STATE §8.1).

## LLM04:2025 — Data and Model Poisoning

**Threat as it applies to LQ.AI.** Training-time poisoning is **largely out-of-scope, for a precise reason**: LQ.AI trains nothing — no training pipeline, no fine-tuning, no weights in the repository — so there is no project-side training corpus to poison. The applicable slice is *context* poisoning: a malicious or corrupted document planted in a knowledge base (or a poisoned community skill) skews retrieval-grounded output, and base-model poisoning risk transfers to the operator's provider/model choice.

**Structural controls (in code).**

- Uploads compute SHA-256 over the received bytes and store it as `files.hash_sha256` (`api/app/storage.py`, `api/app/api/files.py`). Object keys are UUIDs, per [ADR 0005](../adr/0005-file-storage-soft-delete-and-key-scheme.md); a stored digest is an integrity reference, not a content-authenticity check or a guarantee that each ordinary download re-verifies bytes. Evidence: [storage.py:204–237](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/storage.py#L204-L237) <!-- code-cite: api/app/storage.py:204-237 -->; [files.py:288–296](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/api/files.py#L288-L296) <!-- code-cite: api/app/api/files.py:288-296 -->.

**Operator-configured controls.** Upload rights follow the deployment's RBAC; KB curation and watch-triggered autonomous processing of new KB documents are operator/user choices (autonomous is opt-in).

**Residual risk.** There is **no content-level poisoning or anomaly detection on ingested documents** (`no evidence yet` — no scanner exists in `api/app/pipeline/`). Base-model poisoning is out-of-scope for the project.

**Operator responsibility.** Source hygiene for KB content (who may upload, from where); provider/model due diligence for the poisoning posture of the models selected.

## LLM07:2025 — System Prompt Leakage

**Threat as it applies to LQ.AI.** LQ.AI inverts the usual posture: the "system prompts" — skills — are **published open-source work product** (`skills/*/SKILL.md`), so extraction of a built-in skill prompt discloses nothing that is not already in the repository. What remains sensitive is operator-authored content that enters prompt assembly: user-created skills, the Organization Profile's standards (`api/app/models/organization_profile.py`), and the per-session confidential context (documents, inputs).

**Structural controls (in code).**

- **Credential separation:** skill prompt assembly accepts skill content, inputs, existing system text and the Organization Profile; it does not accept provider credentials (`gateway/app/skills/assembler.py`). Provider-key resolution is a separate gateway module (`gateway/app/secrets.py`). This does not prevent a user from pasting a secret into their own inputs. Evidence: [assembler.py:398–430](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/skills/assembler.py#L398-L430) <!-- code-cite: gateway/app/skills/assembler.py:398-430 -->; [secrets.py:151–189](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/secrets.py#L151-L189) <!-- code-cite: gateway/app/secrets.py:151-189 -->.
- Logging discipline: routing and audit records carry metadata (provider, model, tier, token counts, cost — `gateway/app/routing_log.py`, `api/app/models/inference.py`), not assembled prompt bodies. Evidence: [routing_log.py:55–88](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/gateway/app/routing_log.py#L55-L88) <!-- code-cite: gateway/app/routing_log.py:55-88 -->; [inference.py:44–95](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/models/inference.py#L44-L95) <!-- code-cite: api/app/models/inference.py:44-95 -->.

**Operator-configured controls.** What goes into the Organization Profile, user skills, and saved prompts is operator/user-authored content; its sensitivity is set by its authors.

**Residual risk.** Prompt-extraction attacks can disclose operator-authored instructions, Organization Profile content or confidential session context. Access to a chat must not be treated as proof of independent authorization to every item included in its assembled prompt. Assess that disclosure alongside LLM02:2025 while retaining this distinct prompt-leakage risk. No dedicated anti-extraction control exists (`no evidence yet`), and none is claimed.

**Operator responsibility.** Never place credentials, keys, or regulated secrets in skills, the Organization Profile, or saved prompts; the prompt surface should be treated as user-visible.

**Threat as it applies to LQ.AI.** Knowledge bases use hybrid PostgreSQL full-text + pgvector retrieval; risks are cross-tenant retrieval leakage, embedding exfiltration or inversion at the provider, and poisoned KB content dominating retrieval (the retrieval face of LLM04:2025).

## LLM09:2025 — Misinformation

**Threat as it applies to LQ.AI.** The signature professional risk: hallucinated authority, misquoted sources, wrong legal conclusions delivered confidently. In legal practice a fabricated citation is a sanctionable event, not an inconvenience.

**Structural controls (in code).** This is the project's most heavily built surface:

- **Routed citation verification cascade** — exact match → tolerant match → either a single LLM paraphrase judge **or** a multi-model ensemble (`api/app/citation/verification.py`; [`docs/citation-engine.md`](../citation-engine.md)). The ensemble replaces the single-judge stage when activated and admitted by the caller's budget check; otherwise the caller falls back to the single judge. A candidate rejected by every routed stage is unverified. Judge agreement is support evidence, not a guarantee that a quotation is exact or a legal conclusion correct. Evidence: [verification.py:553–586](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/citation/verification.py#L553-L586) <!-- code-cite: api/app/citation/verification.py:553-586 -->.
- **Citation Ledger** — a per-turn index of persisted document/case-law/authority citations and tool-source rows, with source IDs and mirrored verification status (`api/app/citation/ledger.py`; migration `0058`). It is not proof that every byte presented to the model was actually read. Evidence: [ledger.py:33–154](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/citation/ledger.py#L33-L154) <!-- code-cite: api/app/citation/ledger.py:33-154 -->.
- **Fiduciary gate** — derives PASS / SUPPORTED / FAIL assertion counts from ledger verification statuses; records `fiduciary_grade`, `supported_only` or `flagged` per message and excludes provenance-only entries (`api/app/citation/gate.py`; migration `0059`; [ADR 0018](../adr/0018-citation-ledger-and-fiduciary-grade-output.md)). The verdict covers recorded assertions, not all prose. Evidence: [gate.py:25–98](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/citation/gate.py#L25-L98) <!-- code-cite: api/app/citation/gate.py:25-98 -->.
- **Treatment signal** — case-law treatment derived from citing opinions, explicitly labeled "derived, not editorial"; it never asserts good-law/bad-law (`api/app/citation/treatment.py`; [ADR 0019](../adr/0019-transparent-validity-treatment-layer.md)). Evidence: [treatment.py:60–90](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/citation/treatment.py#L60-L90) <!-- code-cite: api/app/citation/treatment.py:60-90 -->; [0019-transparent-validity-treatment-layer.md:1–55](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/docs/adr/0019-transparent-validity-treatment-layer.md#L1-L55) <!-- code-cite: docs/adr/0019-transparent-validity-treatment-layer.md:1-55 -->.
- **Provenance separation** — external-source retrieval provenance ("Sources consulted", `api/app/models/message_tool_source.py`) is architecturally distinct from character-verified quotes (`message_citations`) and the two are never conflated. Evidence: [message_tool_source.py:1–43](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/models/message_tool_source.py#L1-L43) <!-- code-cite: api/app/models/message_tool_source.py:1-43 -->.

**Operator-configured controls.** Ensemble verification for high-stakes operations; judge-model selection (`citation_engine` block in `gateway.yaml.example`).

**Residual risk.** The former chunk-boundary extraction gap ([DE-277](../PRD.md#de-277--citation-extractor-fallback-to-document-scan-on-chunk-boundary-miss)) has a full-document fallback when the caller supplies the parent document text; a successful fallback logs `citation_chunk_mismatch`. Candidates still drop when that text is unavailable or the quote cannot be located (`api/app/citation/extraction.py`). Result-content accuracy judging for legal-research results is deferred ([DE-280](../PRD.md#9-deferred-enhancements-and-identified-future-work)); verdict-tier parity between chat and autonomous paths is incomplete (DE-370, DE-371). Most fundamentally: character verification grounds a quote in source text and a semantic judge can label a claim supported; neither verifies the correctness of unquoted reasoning. No confabulation-rate benchmark is published (`no evidence yet`; related measurement work is DE-239's eval-harness track). Evidence: [extraction.py:180–249](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/citation/extraction.py#L180-L249) <!-- code-cite: api/app/citation/extraction.py:180-249 -->.

**Operator responsibility.** Attorney review of all work product remains mandatory; the gate and cascade are decision support for that review, not a replacement. Treat "unverified" renderings as a stop sign.

## LLM10:2025 — Unbounded Consumption

**Threat as it applies to LQ.AI.** Runaway token spend and resource exhaustion: autonomous loops, tabular review across large corpora, treatment-derivation judge passes, ensemble verification fan-out, or plain request flooding — all ultimately billed to the operator's provider keys.

**Structural controls (in code).**

- **R4 economic brake:** ordinary sessions check projected cost before dispatch when `max_cost_usd` is configured; watch/schedule caps propagate into session admission (`api/app/autonomous/cost.py`, `api/app/autonomous/watch_trigger.py`, `api/app/workers/autonomous_worker.py`, `api/app/autonomous/guard.py`). **Operator-configured controls.** `max_cost_usd` on watches/schedules; tier and provider selection (which price book applies); provider-side spend limits on the operator's own keys.

**Residual risk.** R4's estimates are not actual billed spend; missing external-provider cost configuration can fail open to zero cost (`api/app/autonomous/cost.py`, ADR 0016 D-a3). A session with no configured cap has no ordinary-session dollar admission limit. **There is no per-user or deployment-wide spend quota on interactive chat inference** — the gateway meters cost but does not enforce a spend ceiling on the chat path (`no evidence yet`; verified by absence of any quota enforcement in `gateway/app/`). Tabular's mid-run per-cell ensemble cost ceiling is deferred (DE-331, noted in `api/app/tabular/nodes.py`). Evidence: [cost.py:87–131](https://github.com/LegalQuants/lq-ai/blob/5e128d5baf19cc266a134bb63e2aa6d8557b2e8a/api/app/autonomous/cost.py#L87-L131) <!-- code-cite: api/app/autonomous/cost.py:87-131 -->.

**Operator responsibility.** Set spend limits with the provider (the authoritative backstop under BYO-keys); wire cost telemetry into alerting; size autonomous cost caps deliberately rather than accepting defaults.
