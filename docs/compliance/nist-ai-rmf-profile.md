## Scope and limits

A "profile" is NIST's own term for an implementation of the AI RMF functions, categories, and subcategories for a specific technology, sector, and risk tolerance. This document is LQ.AI's profile: it maps every AI RMF 1.0 subcategory, plus every Generative AI Profile risk category, to what the LQ.AI codebase structurally enforces, what the operator's deployment must supply, and what is honestly not yet built.

What this document is **not**:

- **Not a certification.** The AI RMF is voluntary and there is no "AI RMF certified." Risk-management programs belong to the *organization operating the system*. LQ.AI is software the operator deploys; this profile is the project's contribution to the operator's AI-governance program — pre-mapped subcategory responses with evidence citations — not a substitute for that program.
- **Not a claim that every subcategory is satisfied.** Many subcategories are organizational and can only be satisfied by the operator; several MEASURE subcategories are named gaps because the measurement infrastructure ([DE-237](../PRD.md#9-deferred-enhancements-and-identified-future-work) eval harness and its dependents) is unshipped. Honest disclosure of partial alignment is the deliverable, per the project's conservative-posture rule and [docs/HONEST-STATE.md](../HONEST-STATE.md).

**Goals** (the documented design posture): transparent skills, prompts, receipts and citation records; a gateway boundary for inference and tool egress; checks over extracted, eligible citations with matching/support statuses kept distinct; operator-controlled inference-tier choices; economic/temporal/contextual controls on autonomous work; confirmation mechanisms for consequential tool calls. These goals do not establish that every prose claim is verified, that every emitted citation is captured, or that every outbound connection goes through the gateway.

**Non-goals / out of scope**: LQ.AI trains no models (training-data governance subcategories apply only via third-party pre-trained models); LQ.AI runs no SaaS (hosting-organization controls are the operator's); model-internal explainability of third-party LLMs; content-safety filtering beyond what the operator's chosen provider supplies.

**Actors** (from the gateway-boundary threat model, [docs/security/threat-model.md](../security/threat-model.md)): the **operator** (deploys and configures the stack), **workspace users** (in-house counsel using the product), **inference providers** (operator-chosen, keys held only by the gateway), **tool providers** (case-law/MCP endpoints, gateway-brokered), and **network adversaries**.

## How to read this document

Every one of the 72 subcategories appears below with at least a one-line disposition. Coverage of identifiers is not a finding that each alignment claim is satisfied. Corrections with pinned source links were checked at the correction-review canon; retained rows still require the professional and maintainer semantic pass. Rows where the architecture substantively speaks get fuller treatment. Each row carries:

- **Disposition** — applicability to LQ.AI, the project's response, and the operator's responsibility, in prose.
- **Ownership** — exactly one primary class from the taxonomy below.
- **Evidence** — one or more repo paths (code, doc, or test) a reviewer can open to verify the claim, or the explicit state **"No evidence yet"** with the deferral reference. Blank evidence cells are prohibited in this document: a named gap gets fixed; a blank rots silently.

### Ownership taxonomy

| Class | Meaning |
|---|---|
| **Structural** | Enforced in code or shipped as versioned project work product; holds in every deployment without operator action. |
| **Operator-configured** | The project ships the mechanism; the operator must configure or exercise it for the subcategory to be satisfied. |
| **Operator-only** | Fully the operator's (or their organization's) responsibility; the project can at most supply supporting material. Marked explicitly per the mini-PRD acceptance criteria. |
| **Shared** | Real project contribution and real operator obligation; neither alone satisfies the subcategory. |
| **Residual** | The honest primary state is an unmitigated gap on the project side — named with its deferral path (DE-XXX or doc reference). |
| **Out of scope** | The subcategory does not apply to LQ.AI's architecture (reason given in the row). |
